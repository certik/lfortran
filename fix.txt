│                                                                              │
│ Context                                                                      │
│                                                                              │
│ When declaring a local character, dimension(N) array where N is a runtime    │
│ expression (e.g., character, dimension(len(str)) :: tmp), the variable gets  │
│ DescriptorArray physical type. The LLVM codegen allocates the array of       │
│ string_descriptor structs for arr.data, but never allocates the underlying   │
│ flat character buffer that arr.data[0].ptr should point to. When element     │
│ assignment like tmp(i) = str(i:i) is executed, _lfortran_strcpy reads *lhs   │
│ (which is arr.data[0].ptr) and finds it NULL/uninitialized, triggering the   │
│ error.                                                                       │
│                                                                              │
│ For PointerArray character arrays, this works correctly via                  │
│ create_and_setup_string_for_array which calls                                │
│ set_array_of_strings_memory_on_heap. But for DescriptorArray, the generic    │
│ SimpleCMODescriptor::fill_array_details treats string_descriptors as plain   │
│ data elements and doesn't know about the inner character buffer.             │
│                                                                              │
│ Fix                                                                          │
